How the watcher knows it’s a bug 🕵️

it doesn’t understand code — it reads the result

Part 1 · what it is

idea — not built yet 🧠

A quiet helper in the background

Its own little program. Runs beside you — never types in your terminal or editor.

⬇️
🔁

When you save, it re‑runs your checks

It runs the same build/test command you already use — in its own window, on the newest save.

Part 2 · how it spots trouble

🚦

It reads the result, not the code

It can’t read meaning. It just asks one thing: did that pass or fail?

⬇️
🧾

What “fail” looks like

A crash, a test marked failed, a compiler error, or no answer before a timer (a freeze).

Part 3 · the honest bit

⚠️

A red X isn’t always a bug

Red can also mean the tool itself broke, bad settings, you stopped it, or no tests ran. Not the same thing.

⬇️
🕵️

So it sorts every red

Into your code broke · the tool/setup broke · cancelled · not sure. Only a real test fail, crash, or compiler error is worth flagging — and that means a check failed, not always the cause.

⬇️
🙅

Unsure? It touches nothing

It only flags a problem when the evidence is clear, and only auto‑fixes a safe, exact edit. A “not sure” is left alone.

Part 4 · fixing

🔧

Tiny stuff: the language fixes it

Not an AI, not a debugger. It runs the language’s own fixer — cargo fix, ruff --fix, gofmt — then re‑checks.

⬇️
✂️

Small vs big = is there a ready fix?

A tool already holds the exact change → small, auto‑apply. None exists → big.

⬇️
📸

Fixing without clobbering you

It fixes on a copy, then writes back only if your file hasn’t changed since. Saved again mid‑fix? It drops it and redoes. Your editor may still flash a “changed on disk” note.

⬇️
📝

Big → a tidy note for the AI

File, line, what broke, expected vs got (stack if it crashed). Written for the coding AI, not you.

Part 5 · the extras

🔦

The debugger is a magnifying glass

CodeLLDB (Rust), Delve (Go), pdb (Python). Only for a crash or freeze, only to add detail. Best‑effort.

⬇️
🔄

Then the loop, with a brake

AI fixes → save → watcher re‑checks → green = done, or round again — capped so it can’t loop forever.

⬇️
🤫

What it can’t catch

Code that runs fine but gives the wrong answer. That needs a test that says what “right” is.

🎯

The short version

It doesn’t understand bugs. It re‑runs your checks, reads the result, tells real failures from tool noise, and only acts when the evidence is clear: the language’s own tool for tiny stuff, a note to the AI for real problems, a debugger peek for crashes — with a cap.
