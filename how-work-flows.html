from your idea all the way to shipped — in detail

Read it in words

💡 1. Your idea
You think up a new thing to build.
straight to the Manager: You bring a new idea to the Manager yourself — not through Ops.
🗺️ 2. Map it together (Wayfinder)
You + the Manager agree what it is: the specs and the big decisions.
🎯 3. One clear final goal
The idea becomes a single, written goal everyone can point to.
✋ 4. YOUR YES #1 — start it
You green-light the goal.
your yes gate: Nothing is routed down to a team until you say go.
📝 5. PRD — the plan (2 Planners)
Two writers turn the goal into a plan.
Manager guards the plan: Your original idea is kept — no drifting. If a plan drifts, the Manager sends it back.
🦴 6. SDD skeleton
The bare bones of how to build it.
📚 7. Full SDD
The complete build instructions.
🎟️ 8. Feature tickets (job cards)
The plan is cut into small job cards. Each card also says exactly where it fits the full plan (its own mini- SDD).
who carries the papers: Only the Manager moves each paper desk to desk. Everything is filed in the Herdr vault: PRD · SDD · Tickets.
🔴 9. Build each card: RED → GREEN → TIDY
Feature-Tickets writes a failing test = what 'done' looks like (RED). Green-Pass makes it pass (GREEN). Feature-Tickets cleans it up (TIDY). Then the next card.
where the code goes: Real code goes straight into the product repo. A copy is filed beside each card as a backup.
📦 10. Bundle into PRs of 5
Finished cards go out in pull requests — max 5 each; leftovers get their own (8 → 5+3).
⭐ 11. Robot scores each PR out of 5
Greptile grades the code. 5/5 auto-lands on 'staging' (the practice stage). Below 5/5 → see the side note.
if it doesn't score 5/5: Up to 7 tries. Still stuck → the Manager splits it into smaller PRs (no need to ask you) → each split gets its own 7 tries.
✋ then YOUR choice: A split still stuck after its 7 tries → you pick: (a) more tries, or (b) merge it as-is.
🧪 12. Testing gate
Once it's 5/5, ask 4 quick questions: needs testing? tested? scheduled? blocked by keys (API keys etc.)?
✋ YOUR YES #2 — send it live
staging → main is a SEPARATE pull request. It needs a passing test AND your explicit yes. Never automatic.
📍 YOU ARE HERE → PR #6
PR #6 is exactly this yes. Approving it ships the tested rules from staging to main, so every team gets them.

👥 Who talks to who

  • Chain: Agent → Manager → Ops → YOU. Your reply comes back down the same way.
  • Managers never message you directly — even decisions go through Ops.
  • An agent tells its Manager the instant a job is done — it never goes quiet.
  • Manager silent for 1 hour → the agent goes straight to Ops → Ops tells you.
  • "No change" is just logged; only real blockers, decisions, or questions reach you.
  • Every message starts with a label: "Sender -> Receiver:".
  • The Manager never trusts "done" on a word — checks the real commit, test count, and score.

🔁 The heartbeat — every day

  • Work blocks: B1 09:00–13:00 · B2 14:00–17:00 · B3 18:00–20:00 (with breaks).
  • 4 reports a block: Spaceship (15 min before) · End-of-block · Blocker (hard only) · PR table.
  • Ops waits for 2+ teams (a 30-min window), then tells you — never pings you for one team alone.
  • After 30 min with no reply, a team carries on with pre-approved work — never idle; it returns the moment you reply.
  • Every pause writes a handoff note: commit + push, then branch, last commit, % done, next steps, blockers, last 3 handoffs (+ session IDs), chat links, watch-outs.
  • "Done" is graded, not trusted: the author writes the checklist, the Manager grades it; your only sign-off is ship-to-main.
  • Every decision to you carries 3 things: how big? · what else? · what if we don't? (+ an ELI5 link).

🎨 Who's who

  • YOU (Bobby) — the boss — has the ideas and gives the two big yeses
  • Ops — the messenger — carries messages between the Manager and you, and batches them
  • Manager — runs one team; the only one you talk to
  • Planners / Writers — turn your goal into the plan (PRD) and the build instructions (SDD)
  • Builders — Feature-Tickets writes the tests + tidies; Green-Pass makes them pass
  • Greptile robot — scores each pull request out of 5
  • staging / main — staging = the practice stage; main = the live shelf every team builds from
