The tester kit 🧰

what changed in Feature Map, in plain words

1 🧰

We borrowed a good toolbox

A developer named Lauren Tan gives away a toolkit (“pstack”). Its best idea: a driver's manual that lets an AI use an app the way a person would — click the real buttons, check what shows up. We took her verification parts into our skill, with her name on them.

⬇️
2 📖

Now each idea gets two things

One: the blueprint page — the map you read on your phone. Two: a tester kit (called verify-<app>) that lives in the app's own code folder. You read the page. The tester agent runs the kit.

⬇️
3 🗺️

Our map turns into the kit

The checkpoints we write (“open the exchange, the stop-loss is visible”) become the kit's recipes. Our green Success boxes become its “this is what proof looks like”. Nothing is written twice — the map feeds the kit.

⬇️
4 🎬

The tester agent does the work

It starts the app, drives each feature like a user, and ProofShot records video of it all. Your only job: watch the recording. You never run a test.

⬇️
5 🔄

It stays fresh on its own

You add a thought to an idea → the map updates the same moment. The app code changes → a maintenance pass re-checks the kit against reality and fixes what drifted.

⬇️
6 ⏳

Nothing changes today

The memecoin idea has no app yet — nothing to drive. The day code exists, the kit gets built inside it, and the tester agent runs it with the camera on.

Short version: the page is for your eyes, the kit is for the tester agent — same map feeds both, proof comes back as video.
