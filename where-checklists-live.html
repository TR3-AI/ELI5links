The “done” lists:
how many, and where? 📋

two questions, plain answers

1 · HOW MANY LISTS?
✅

One per small job, one per batch

A list for each small job (a ticket), and a list for each batch (a phase). Those are the two we use.

❌

A giant one for the whole project?

No. All the batches added together already are the whole project. A giant list would just repeat “all batches done” — extra work, nothing new.

🎯

One catch: the last batch

The final batch gets one extra check: “does the finished thing match what you asked for at the start?” so nothing drifted along the way. One extra box — not a new list.

⬇️
2 · WHERE DO THEY LIVE?
🧰

In the shared toolbox

The real copy lives in the toolbox everyone shares — the product repo on GitHub, where the code, tests, and grades already are. Every agent can see and use it. A reading copy sits at home (the Vault 🏠) for browsing.

🎫Small-job list → with its ticket, and its tests in the toolbox.
📦Batch list → in the plan, and its end-to-end test in the toolbox.
⬇️
🗄️

Don’t mix these two up

📝 The “where I stopped” note → the team’s shared drop-box (cloud memory).

📋 The “what done means” list → with the specs (toolbox + home).

Different jobs, different drawers.
