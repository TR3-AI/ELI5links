Move your OMP setup 🧳

To another computer, or the cloud — same setup, no re-setup

💡

The big idea

Your whole OMP folder is ~5.4 GB, but only ~25 MB is the part that matters. That 25 MB is THREE things: your global config, your OMP-5 profile, and your OMP-Moon profile. Copy those three, skip the big rebuildable junk, and OMP runs the same on the new machine.

⬇️
1 🌐

The GLOBAL config (shared by every profile)

Copy these top-level files in ~/.omp:
• ~/.omp/config.yml — your global settings (the shared model-roles default).
• ~/.omp/marketplaces.json — your list of plugin marketplaces.
• the default ~/.omp/agent/ folder — its config.yml, your .env, your skills / extensions / rules, and agent/agent.db (the default profile’s logins).

⬇️
2 🗂️

Your two named profiles, side by side

OMP-5 — ~/.omp/profiles/5/
• config.yml — OMP-5’s own settings.
• agent/ folder — its config, skills, .env.
• agent/agent.db — OMP-5’s logins live in here.
• auth-broker.token — OMP-5 ONLY. OMP-5 also uses a local auth-broker (auth.broker.url = http://127.0.0.1:8755) — see Part 4.

OMP-Moon — ~/.omp/profiles/moon/
• config.yml — OMP-Moon’s own settings.
• agent/ folder — its config, skills, .env.
• agent/agent.db — OMP-Moon’s logins live in here.
• NO auth-broker.token and NO auth.broker.url. OMP-Moon has no separate token — it just uses its own agent.db logins. Nothing to copy there, and that is NOT an error.

⬇️
🗑️

Skip everywhere (global + both profiles)

logs/, cache/, run/, puppeteer/ (downloaded Chrome), and old chat sessions/. Big and self-rebuilding — copying run/ can even break things.

⬇️
3 🔀

Move it safely — pick ONE route

A) Another computer
1. rsync -a (or scp) once. -a keeps the secret files’ locked permissions.
2. For each agent.db (global, OMP-5, OMP-Moon) do NOT copy the file raw — run sqlite3 old.db ".backup new.db" for a clean copy.
3. On the new machine chmod 600 every copied agent.db, .env, and token file.

B) Cloud
1. A PRIVATE git / dotfiles repo for the text settings only, with a .gitignore that blocks agent.db, .env, and token files — never push a login.
2. Move the secret files once, by hand, over a secure copy — not through the synced folder.
3. Never point iCloud / Dropbox at a live agent.db / .env / token while OMP is running (it grabs half-written files and corrupts them).

⬇️
4 🔑

Logins

Each profile’s logins ride inside its own agent.db, so copying it brings them along — no logging in again (tested: a copied setup replied from real providers with zero login prompts). ONE exception: OMP-5’s auth-broker. On the new machine either start it (omp auth-broker serve) or switch OMP-5 to its own copied logins with one line: omp config reset auth.broker.url. OMP-Moon and the default profile need nothing extra.

⬇️
5 🔒

One safety fix, do it now

~/.omp/profiles/moon/agent/.env is readable by anyone on the machine (mode 644) but holds raw API keys. Lock it: chmod 600 ~/.omp/profiles/moon/agent/.env.
