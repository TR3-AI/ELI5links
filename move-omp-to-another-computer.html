Move your OMP setup 🧳

To another computer, or the cloud — same setup, no re-setup

💡

The big idea

Your whole OMP folder is 5.4 GB, but only about 25 MB is the “real you” — your settings and your logins. Copy that small part, skip the big rebuildable junk, and OMP works exactly the same on the new machine.

⬇️
1 📦

Copy the important ~25 MB, skip the rest

COPY: your config files, your skills / extensions / rules, and your login vault — the agent.db file inside each profile — plus the .env files and profile 5’s auth-broker.token.

SKIP: logs/, cache/, the run/ folder, the downloaded Chrome (puppeteer/), and old chat sessions/. These are big and rebuild themselves; copying run/ can even break things (it holds live sockets for the machine you’re leaving).

⬇️
2 🔀

Pick ONE of two ways to move it

A) Straight to another computer
1. Copy once with rsync -a (or scp). The -a keeps the secret files’ locked permissions.
2. For each agent.db, do NOT copy the file raw — it’s a live database. Run sqlite3 old.db ".backup new.db" to get a clean copy.
3. On the new machine, lock the secret files: chmod 600 on every agent.db, every .env, and every token file.

B) Through the cloud
1. Put ONLY the text settings in a PRIVATE git / dotfiles repo. Add a .gitignore that blocks agent.db, .env, and token files — never push a login to the cloud.
2. Move the secret files (agent.db / .env / token) once, by hand, over a secure copy — not through the synced folder.
3. Never point iCloud / Dropbox / Google Drive at a live agent.db / .env / token while OMP is running — it grabs half-written files and corrupts them.

⬇️
3 🔑

Your logins come with you

Your logins live inside agent.db, so once you copy it they just work — no logging in again (this was tested: a copied setup answered from real providers with zero login prompts). ONE exception: profile 5 uses a local “auth broker.” On the new machine either (a) start it: omp auth-broker serve, or (b) turn it off with one line so it uses the copied logins instead: omp config reset auth.broker.url.

⬇️
4 🔒

One safety fix, do it now

Your profiles/moon/agent/.env is readable by anyone on the machine (mode 644) even though it holds raw API keys. Lock it: chmod 600 ~/.omp/profiles/moon/agent/.env.

Tested for real — the ~25 MB essential set was copied into a fresh HOME and OMP ran identically (version, config path, and live model replies on the default, moon, and profile-5 setups). Full technical method: omp-portability-method.md.
