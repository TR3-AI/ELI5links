What Greptile is

Greptile is a robot that reads a pull request and gives it a score out of 5. That number is its whole job. It does not decide whether the work is right.

⬇️
🏅

Check #1 — Clean?

Greptile's 5/5 is the Clean? check — is the code tidy and up to standard? Hit 5/5 and this half is cleared. That is all Greptile does.

⬇️
🧹

The 12 "smells" aren't Greptile's job

Before the pull request, Feature Tickets cleans its own code against a fixed list of 12 "code smells." That's the worker tidying first. Greptile just scores what comes out — it doesn't run the list.

⬇️
🧑‍⚖️

Check #2 — Right?

Does the code do exactly what the ticket asked? That's the Full SDD seat — it wrote the plan but not the code, so it's a real outside opinion. The manager hands it the diff and enforces the answer.

⬇️
🚦

Both must pass

A pull request only auto-merges to staging if both pass — Greptile 5/5 and Full SDD says it matches the ticket. A Right? fail sends it back even at a perfect 5/5.

⬇️
👷

The worker doesn't grade itself

Feature Tickets gives its own change a quick glance before the PR — a first filter, never the verdict. It never signs off its own work.

⬇️
📦

Is it live yet? Not yet.

It's all written and saved in two pull requests — #29 (the rulebook) and #39 (the tool) — but not switched on. It reaches the teams only after you approve the merges and the setup re-runs. Nothing merges without your yes.

Short version: Greptile = a score out of 5 (Clean?). Full SDD = a real reviewer (Right?). Both must pass. Written and waiting on your yes.
