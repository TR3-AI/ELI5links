Catching a bad commit 🛡️

you asked: if we block it, then what? here’s the whole plan

👀

First, what the watcher already does

It sits in the background, and when you save it re-runs your build and tests. It reads the result (pass or fail), sorts a real failure from tool noise, auto-fixes tiny safe stuff, and writes a note for the coding AI on the rest. Full walkthrough: how the watcher knows →

⬇️
🚫

“Block a bad commit” = the gate

This is the piece I called Enforce. If the build or tests are red, it won’t let that broken code be saved or shipped. That’s the safety catch — nothing red slips through by accident.

⬇️
🔄

But we don’t just block — we act on it

1. Try the safe fix. The language’s own fixer has a go. Goes green? It just goes through, already fixed — no fuss.

2. Can’t auto-fix? Block + hand it over. The commit is held, and the exact finding (file, line, what broke) goes to the Developer to fix, then re-check.

3. There’s a brake. The fix-and-recheck loop is capped so it can never spin forever.

4. Still red after the cap? It escalates. It comes up to me (and you) with the finding — never a silent, stuck block.

So a caught commit is always one of: fixed, sent back to be fixed, or raised to a human. It never just dies quietly.
