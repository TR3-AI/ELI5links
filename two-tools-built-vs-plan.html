Idea Baker and Mr Tester — what each really does, and where the build drifted from the plan. Both managers wrote these from the actual code.

🧠 1
Idea Baker — what it does

You run /skill:idea-baker. It opens 3 AI “voices” in their own panes (Grok, Fable, GPT). You ask a question → it sends it to all three → Opus boils the answers into one first-principles reply → logs the whole Q&A to a GitHub issue (one per project). You conclude, it structures the idea (Intent / Steps / Flow), then flips the pane to Fable and grills you with sharp questions. It’s an OMP skill (Bun scripts), not a running service. 105 tests pass.

Idea Baker — the 4 drifts

🎬 4
Mr Tester — what it does

Feed it a feature’s code + a plain spec. It drives the feature, records a video + a named screenshot per step, and writes a report where every row links the exact code line — plus an optional Andrew voice-over. Three lanes: web (the main path, drives ProofShot), terminal (records a real terminal run), and desktop (Phase 5 — on a branch, not merged, needs the Mac permission).

⬇️
⚠️ 5
Mr Tester — matches the plan?

Core matches: the six-field report, web capture, per-step screenshots, and the voice-over all landed. 5 drifts: the terminal lane was built standalone, not inside the ProofShot fork; “one engine” became three; the fork isn’t actually the engine (it drives the stock ProofShot); narration is home-made, not the named reuse skills; the ELI5 page it makes is saved locally, never published.
2 gaps: only run on a toy toggle so far (never a real feature), and the live desktop run is still held.
