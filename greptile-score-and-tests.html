Greptile score & the test 📋

your two questions, straight

1 · would the debugger or autofix lift your Greptile score?

⭐

The debugger: no effect

Greptile scores the code in your pull request. The debugger never changes that code — it only helps you find a crash while building. So it moves the score by zero.

⬇️
🧹

Autofix: barely, and not needed

Autofix could tidy small style nits — but the gate already runs clippy + fmt to do exactly that, safely. So you don't need autofix for the score.

⬇️
📈

What actually pushes 4 → 5

(1) No broken build or failing test reaches the PR — lifts the floor. (2) clippy + fmt kill style nits. (3) The AI judge flags logic + security holes in the gate. (4) Keep each change small. Those are the levers — not the debugger or autofix.

2 · what is “the test”?

🎯

It pins down what “right” means

A test is a tiny piece of code: run your real code with a known input, then check the answer is what you expect.

⬇️
🧮

A plain example

Say add_tax(100) should give 108. The test says: add_tax(100) == 108. Break the math so it returns 100 → the test goes red, caught. With no test, that wrong answer sails through — it still builds, nothing complains.

⬇️
🧰

Three kinds

Unit — one function's answer. Invariant — a rule that must always hold (“total never negative”). Acceptance — a whole feature does what you asked. The important ones get locked so the AI can't weaken them.

⬇️
✍️

Who writes them

The coding AI writes them as it builds; the important acceptance ones you (or a separate agent) own and lock. That's already in the plan — the protected acceptance/ tests.

✅

Bottom line

The debugger and autofix don't earn you a 5 — catching red early, clippy/fmt, the AI judge, and small diffs do. And the only thing that catches a quiet wrong answer is a test that says what “right” looks like.
