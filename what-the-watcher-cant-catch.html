What the bug-watcher can’t catch 🕳️

You asked about the bugs it misses. Here’s the honest gap — and the fix.

🐶 1

What it does

It watches your files. Every time you save, it re-runs the build and the tests. Green → fine. Red → it steps in.

⬇️
✅ 2

So it catches

Anything that breaks the build or fails a test — crashes, type errors, a test that turns red. That part it’s great at.

⬇️
🕳️ 3

The blind spot

Code that builds fine and passes every test but still gives the wrong answer. If no test checks for the right answer, the watcher sees green and waves it through.

⬇️
🧮 4

A plain example

A function should add: 2 + 2. It returns 5. If nothing tests “expect 4”, the build passes, the tests pass, the watcher is happy — and the bug ships.

⬇️
🧷 5

Fix 1 — a correctness test

Write one test that pins the right answer (“expect 4”). Now a wrong answer turns that test red, and the watcher catches it like any other failure. Cheap, and it works today.

⬇️
🧑‍⚖️ 6

Fix 2 — the AI judge (planned)

A second reader that checks the change against what you actually asked for, not just “does it run”. It catches wrong-but-passing work. This is on the plan — not built yet.

⬇️
🎯 7

Bottom line

The watcher guards “does it run and pass?” It can’t guard “is it correct?” on its own. Correctness needs a test that knows the right answer — or the AI judge.

Short version: it catches red, not wrong. Give it a test with the right answer (or add the AI judge) and wrong-but-passing bugs stop slipping through.
