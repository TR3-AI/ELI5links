The bug-watcher — step by step 🐛

what happens the moment you save a file

1 💾

You hit save — it notices

The watcher is always listening. One save (or a quick burst of saves) becomes one check. It ignores the noise — build folders, .git — so it only reacts to real code changes. (This is the very first thing that happens.)

⬇️
2 🏃

It runs your checks — safely

It builds your code, then runs the tests — each in its own walled-off process with a time limit. If something hangs too long, it kills the whole thing so nothing jams up.

⬇️
3 🧭

It decides what really happened

Honest labels: passed, a real code failure, a tool or setup problem, cancelled, or unknown. A crash or a freeze gets its own flag. It only says “green” if everything truly passed — never a maybe.

⬇️
4 🗸

It can auto-fix — only if you ask, only safely

With the fix option on, it takes a fingerprint of your files, fixes on a copy, and writes a fix back only if you haven’t touched that file since. If you did, it skips and tries next time.

⬇️
5 📝

It writes down the findings

A tidy machine-readable list (findings.json) plus a one-line human summary — so you, or an AI, can act on it right away.

⬇️
6 🐛

Next up: replay under a debugger

The plan: when something crashes or freezes, replay it under a real debugger — CodeLLDB for Rust — to pin the exact spot. A reviewer step comes too. Both are planned, not built yet.

⬇️
7 📦

Where it stands today

Only the watcher above actually exists — and it’s sitting in a pull request waiting for your OK. 0 of 11 known bugs fixed so far. The reviewer and debugger aren’t built yet.

Short version: save a file → it builds + tests safely → labels the result honestly → optionally auto-fixes → writes the findings. The debugger replay is next, not built.
