Why the video proved nothing

The map was born with the P-stack — its very first commit is titled “P-stack pass,” and the rule was added an hour before the map existed. There was never a plain “before.” Two P-stack maps looking alike tells you nothing about the P-stack.

Why it looked “identical”

Not a bug. The skill’s rule is “keep stable features, only touch new or changed ones.” The input already had a finished map, so the run verified and kept it. Same input → same map. Expected, not proof either way.

⬇️

The real test we ran

Two fresh, from-scratch maps on the same input, fully offline (no GitHub), the old map removed so neither could just keep it — one with the ~600 P-stack lines, one with them stripped out. The only difference between them: the P-stack.

⬇️
5
📊

The result: clearly different

The two maps share only 12% of their text. The no-P-stack map is 1.67× bigger (58KB vs 35KB). Same ~22-feature backbone, but the wording, density and naming are very different. (I re-ran these numbers myself.)

⬇️
6
✂️

What the P-stack actually does

It doesn’t change which features get found — that comes from other rules. It’s a writing-style + principles layer: it makes the map about 40% tighter and terser for the same features. Real — and exactly what those principles are meant to do.
