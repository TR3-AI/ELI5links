The cloud gate & the two AIs ☁️

the un-cheatable checkpoint, explained

Part 1 · the cloud gate

💻

Two places a check can run

On your machine (local), or on GitHub's computers — “the cloud.” The cloud gate runs up there, not on your laptop.

⬇️
🔓

Why not just check on your machine?

The coding AI runs on your machine, as you — it can run any command, so it could switch off or fudge a check that lives there. That's why the local check is only a soft warning.

⬇️
🔒

The cloud is out of its reach

The cloud gate runs on a separate computer the AI can't touch. GitHub itself refuses to merge the pull request unless it passes — and the AI can't override GitHub's own rule. That's the hard block.

⬇️
⚙️

What runs inside it

R1 (rules only, no AI): re-runs the locked tests, checks nobody weakened them, runs clippy + fmt. Then R2 (the AI judge): is it actually right? Only you can bypass — the AI's identity can't.

Part 2 · one AI, or two?

👥

Two — kept apart on purpose

AI #1 — the coder: writes the code, on your machine. AI #2 — the judge: a separate one, running only in the cloud, that reads the finished change.

⬇️
🚫

Why two?

So the coder can't grade its own homework. If one AI both wrote and judged, it could go easy on itself — or hold the judge's key and tamper with the verdict.

⬇️
🔑

The judge's key never touches the coder

It lives in the cloud, never on the coding machine. The coder can't reach it, can't run the judge, can't change the verdict. (It can be the same brand of AI — just a separate one, walled off.)

✅

In one breath

The cloud gate is the checkpoint on GitHub's own computers that must pass before a merge — a rules-only check (R1), then a second, separate AI judge (R2). Two AIs, walled apart so the one writing the code can never mark its own work.
