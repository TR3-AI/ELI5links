Why checking on every save helps your score ⭐

Greptile is the reviewer. It grades your work 1–5. You want a 5.

🤖

A robot writes your code

It's fast, but it slips up — a build that won't compile, a test that fails, a little mess here and there.

⬇️
👀

A watcher checks its work — every save

Each time the robot saves, a little tool re-runs your real build and tests. Those are hard to fake: the code either compiles and passes, or it doesn't.

⬇️
🧹

This clears the easy fails

A broken build or a failing test almost never gets a top score. Catching those on save means they never reach the review. That lifts the floor.

⬇️
⚖️

But a 5 needs more than "it builds"

The reviewer can't be won by a green build alone. A 5 needs things the watcher can't see: code that runs but is wrong, security holes, messy structure, missing edge cases, or one giant change.

How to actually earn the 5

Add clippy + fmt to the gate (kills the style nits), run a quick review — the same AI judge — before the reviewer sees it, and keep each change small.

⭐

The short version

Checking on every save raises your odds mostly by removing the easy losses — a guaranteed-green build and tests. The extra points come from the review layer, not the watcher alone. Passing checks isn't the same as correct, and a green build and tests isn't automatically a 5.
