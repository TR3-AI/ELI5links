Unified planning, parallel departments 🏗️

plan it once as one whole thing — then build the slices all at once

1 🏛️

Two kinds of team

One permanent core team (1 manager + 8 agents) does all the thinking and never closes. Under it, temporary teams do the building and close the moment their slice is done.

⬇️
2 🧠

First, plan it as one whole project

Same front half you run today: idea → research → you approve the cost → two planners draft → first Plannotator goal → Wayfinder → the Gold Plan (the final approved plan, the boss document) → you approve it. Nothing splits until the Gold Plan is signed off.

⬇️
3 ✂️

Cut the plan into departments

The same two planners slice the Gold Plan into real build sections — e.g. API, Data, Front-End. Each gets its own mini-plan (PRD). They check all the pieces fit, then pack a handoff for each one.

⬇️
4 ⚡

Build every department at once

A tool called AUTOPANE spins up a temporary 9-pane team per department. Each runs the exact build chain you already have (design → tickets → test-first red / green / refactor). They all run in parallel, on their own branches.

⬇️
5 🧩

Glue it all back together

Each department hands its finished branch back. The core team merges them all into one project branch, runs full-system tests, then promotes to main — with your OK.

⬇️
6 🚪

Close the temps, keep the core

Once a department is merged and accepted, its tab closes. The core team stays open and keeps every record — research, goals, Gold Plan, PRDs, tests, branch history.

⬇️
7 🧭

The rules that stop drift

Gold Plan is boss. Departments can read the whole plan but only build their slice. Shared interfaces are owned centrally. Any big change goes back up to the core team. One owner per requirement — no overlaps.
