How the watcher fixes things 🔧

small stuff itself — big stuff back to the AI

Part 1 · small, safe fixes

idea — not built yet 🤏

Small fixes: no AI

For tiny, safe stuff it uses each language's own fix tool — not an AI.

⬇️
🧹

Like what?

Tidy imports, formatting, a rename the compiler literally suggests, drop an unused bit. cargo fix, ruff --fix, gofmt.

⬇️
🙅

Why not an AI for those?

The tool already knows the exact change. Less guessing = lower risk. It re‑checks right after, to be sure.

Part 2 · the real bugs

📝

Bigger bug → a tidy note

File, line, what broke, expected vs got (and the stack, if it crashed).

⬇️
🤖

The note goes to the AI, not you

You're not the one coding — the AI is. So the note is written for the AI to act on, not for a human to read.

Part 3 · how the AI gets it

🔌

If the AI runs the watcher

The note comes back as the tool's answer — dropped straight into the chat as the next thing the AI sees. Its next move: fix them.

⬇️
📥

If it runs in the background

It saves the note to a file (findings.json), and whatever drives the AI posts it as the AI's next message. Nothing can reach into the AI — the note always arrives as its next input.

⬇️
🔁

Then the loop

AI fixes → saves → watcher re‑checks → green = done, or round again.

⬇️
🛑

With a brake

A limit on tries, so it can't loop forever. After a few goes, it stops and flags a human.

🎯

The short version

Small, safe stuff → the language's own fix tool (no AI). Real bugs → a tidy note handed to the AI — as a tool result, or posted as its next message — then AI fixes, watcher re‑checks. Green, or try again, with a cap.
