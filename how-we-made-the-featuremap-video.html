How we made the tutorial video 🎬

the honest recipe — and what MrTester learns from it

🎬
This is the honest recipe

Here's exactly how that ~2.5 minute /featuremap video got filmed and edited — no hand-waving, no invented steps. This whole recipe is what's moving into MrTester as a reusable tool, so it can film a clean, narrated demo of anything the same way.

⬇️
📺
What the video actually shows

One narrated run: the /featuremap skill fires live on a real idea link, the map it builds is shown on its own real live page, then the map's earlier version and its new version are placed side by side with what changed boxed in. Finished file: picture and spoken narration together, about 2 minutes 31 seconds, roughly 21 MB.

⬇️
🔒
The trick: it was never screen-recorded

Macs have a privacy guard called TCC that blocks automated tools from silently recording your screen. So instead, a small go-between program (a PTY bridge) runs the real terminal inside a fake terminal it controls, and streams every character it prints straight to a web page. That page shows it using xterm.js — a terminal that lives entirely inside a browser tab and behaves just like a real one.

⬇️
🤖
A robot browser does the typing — and the filming

Playwright (a browser-automation tool) opens a real Chrome browser with no visible window — "headless" — and types the demo into that web-page terminal like a person would. To make the video, it takes a fast stream of screenshots of the page and feeds them straight into ffmpeg (a video tool), which stitches them into a video frame by frame. It does not use a built-in screen-video recorder; that was only ever used for quick throwaway test checks, never the real footage. It also locks itself down: its terminal code is bundled inside it instead of pulled fresh off the internet, and it only obeys commands carrying a secret one-time code sent from that exact page.

⬇️
🧭
About that "address bar" you see

Because the browser has no visible window, there's no real address bar either. Whenever the video shows a web address, it's a truthful overlay drawn onto the page itself — it reads the page's real, actual address and displays it. It's the genuine link, honestly shown — just drawn by the page, not by the operating system's browser window frame and address bar.

⬇️
1 ⌨️
You type the command, live

It starts on an empty box and types /featuremap plus the idea link, letter by letter, into that browser-page terminal — nothing pre-filled, so it's clearly a real run happening in front of you.

⬇️
2 ⚙️
The skill builds the map, on camera

The command runs for real and prints the new feature-map's link straight into the terminal, live.

⬇️
3 🔗
The exact new page, full screen

The new map opens full-screen at its versioned "v2" link — byte-for-byte the same page the skill's printed link serves — with the honest on-page address overlay showing its real web address. The actual live page, not a preview or a mock-up.

⬇️
4 🆚
Old map next to new map

Version one on the left, version two on the right — two real, live feature-map pages shown side by side, scrolling together, both checked byte-for-byte against the real site first. The exact sentences that changed are boxed on both sides.

⬇️
5 🗣️
Narrated the whole way through

A spoken voice explains each part as it happens, start to finish — how that voice was made is below.

⬇️
✂️
How it was edited

Filming came out as two recordings — one covering steps 1-2, one covering steps 3-4 — which get cut and joined into a single silent video. Then it's checked over: one pass scans the sound for any awkward gap of silence, another scans every frame of picture to check that none of it went black, and the join points themselves get checked by pulling out individual frames.

⬇️
🎙️
How the narration was made

The script was written as five short pieces, one per step. Each one was turned into speech with edge-tts — a free tool that reads text aloud using a neural voice (a computer voice modelled on real human speech by an AI, not an old robotic reader, and not a person in a booth). The original video used a British voice; the version headed into MrTester swaps in an American voice instead — same tool, just a different voice picked.

⬇️
🎚️
Syncing voice to video

Each of the five spoken clips is placed onto the silent video at an exact starting moment — 0.0s, 24.0s, 54.1s, 72.7s and 116.5s in — so it lands right next to what it's describing, then mixed in. The finished mix comes out at a healthy, comfortable volume, about -22 dB — not too quiet, not blown out.

⬇️
✅
The quality checks

Before shipping, the file gets checked that it's really a proper video-plus-audio file of the right length, that the volume is sane and nothing clips, that the silence and black-frame checks still pass, and that still frames pulled from the video actually show the right thing — the real address overlay, and the old-vs-new comparison with the changes boxed.

⬇️
📱
How it's delivered — onto a phone

The finished file gets a quick rewrite that moves its internal index to the very front, so a phone can start playing it before the whole thing has downloaded. It's served by a small web server that can hand over just one chunk of the file at a time — so you can skip around instead of only watching start to finish — and a tunnelling tool opens a temporary public web link straight to it, good enough to watch and scrub through on a phone.

⬇️
🚧
The honest safety note — the real lesson

The tool has an optional safety switch that points a recording session at fake stand-ins instead of the real project, so nothing it does can cause harm. For this recording the switch was on and proven, not assumed: the session ran inside a throwaway copy of the project, the GitHub command-line tool was swapped for a stub that fails every call, every network path to GitHub was cut, and the session stopped on camera at "held at publish" — the real project's main branch sat untouched the whole time. Publishing happened later, by a person, from a clean copy, under the owner's standing rule for this site. The lesson that forced all this: an earlier, discarded run had slipped past a computer-local check by pushing from a second copy of the project — so a check that lives only on one computer isn't a real lock. What actually works: a rule GitHub itself enforces on the important branch, a login that simply can't reach it, or a throwaway workspace with no access to the real thing at all.

⬇️
🧰
What this becomes in MrTester

Every piece of this — the terminal go-between, the browser-page terminal, the robot browser that types and takes the screenshots, the video stitching, the edit checks, the AI narration, and the phone-friendly delivery — is moving into MrTester as one reusable recording skill. Point it at any live session, and it can film the same kind of clean, narrated, honest demo, any time.

Short version: no screen was ever recorded — a fake terminal in a browser tab was filmed by a robot browser, screenshot by screenshot, then edited, narrated and checked before it shipped.
