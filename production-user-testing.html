Production user testing 🧪

prove it works where the user looks — on video, every phase

1 🐛

Tests pass, the app can still be broken

Backend tests can all pass while the thing misbehaves where the user actually looks — the order never reaching the exchange, the stop-loss that just sits there. Passing code is not proof.

⬇️
2 🤖

A robot test-drives it like a real user

A tester agent drives the real app — clicks, types, watches — while ProofShot records video of every step. Never Bobby; Bobby just watches the recording.

⬇️
3 📋

It tests from an exact list

Before anything runs, the manager hands over numbered checks — the test stream: what to try, what you should see, and what proves it's broken. One check per feature and per sub-feature. No guessing.

⬇️
4 🔁

Broken? Back it goes

Every failure — with its video, timestamps, and context — goes back to the agent that built the feature. It fixes, the robot re-tests, until every check ticks green.

⬇️
5 🚦

No green video, no next phase

This runs every phase, not at the end of the project. Small proven tests stack into a phase, phases stack into the project — so deep flaws surface before you build on top of them. Green video is the only currency.

⬇️
6 🔗

It also watches the code

Point it at a repository: it reads the code, watches feature branches for new work, figures out what the feature is and how to test it, then marks it "ready to be tested". Documents and tickets still work too — the repo is just one more input.

Short version: a robot uses the app like you would, on camera — and nothing ships until the video proves it works.
