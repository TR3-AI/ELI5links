The watcher: built, gaps & the fix loop 🔄

what works today, what's missing, and how we force the AI to fix what it breaks

🧭

The big idea

Don't trust the AI's word. Check its work every time code is saved — not at the very end. The watcher is the checker; findings.json is the receipt; the hard part is forcing the AI to act on it.

Part 1 · what's built today

built ✅

A real Rust v1 — it works

A working command-line tool. It builds clean and 39 of its own tests pass. This part is real, not a sketch.

⬇️
🔄

How it works

You run it in its own terminal. On save it re-runs cargo build + cargo test, reads the result, writes findings.json, and prints green ✓ or a short summary.

⬇️
🚦

It reads facts, not vibes

Timeout → freeze. Fatal signal → crash. Compiler error → build broke. Failed test → test broke. Green only when everything passes.

⬇️
built 🔧

Tiny auto-fixes

With --autofix it runs Rust's own fixers (cargo fix, clippy --fix, fmt) on a scratch copy, then re-checks. No AI, no guessing.

Part 2 · what's NOT built yet

not built 🚪

The enforcement — the missing heart

Nothing yet forces the AI to read the receipt or fix before it moves on. Detecting is done; making the AI act is not. (That's Part 6.)

⬇️
not built 🦀

Only Rust

No Python, Go, or JavaScript yet. One language adapter exists.

⬇️
not built 🔦

No debugger

CodeLLDB isn't wired in. Planned only: a best-effort peek after a crash or freeze for extra detail — never a decider.

⬇️
not tested 🧪

The live watch loop is unproven

Only the one-shot --once run is tested. The keep-watching loop is written but not exercised end to end.

Part 3 · gaps, flaws & future errors

known flaw 🟢

It says "success" even when it finds bugs

The program always exits 0 (the "all good" code), even with findings. Any gate that checks the exit code is fooled. Red must exit non-zero.

⬇️
known gap 📋

A blank receipt

When a check can't run (bad setup) or is unclear, it's not green — but findings.json can still come out empty and say "no findings." The note must always explain.

⬇️
known flaw ✂️

Auto-fix is too eager

Any compiler suggestion with a replacement — even a "maybe wrong" one — fires all three fixers across the whole project (reformatting, unrelated lints), not just the one spot.

⬇️
known flaw 🔀

"expected vs got" can flip

Test values are labelled by position, so your real value can show up under "expected."

⬇️
the hard limit 🕵️

Silent wrong answers

Code that runs fine but returns the wrong result is invisible — unless a test says what "right" is. No checker can guess your intent.

⬇️
known gap 🚫

No project? Silent pass

Point it at a non-Rust repo and it just exits, looking fine. It should say "I can't check this."

⬇️
future risk ⏱️

Slow on big repos

A full build + test on every save can drag. Later it needs smarter scoping and caching so it stays snappy.

Part 4 · the whole point

🧠

Check as you go, not at the end

Old way: let the AI run all the way to the finish, then hope. New way: verify every save, catch the break the moment it happens — so you always know what's actually working.

⬇️
🔒

Why it can't be fudged

The judge is the compiler and the tests, not the AI's opinion. The AI can't talk a red into a green.

Part 5 · findings.json — how you KNOW

built 🧾

Every check leaves a receipt

findings.json lists each problem: tool, kind, file, line, expected, got, message, and whether it's auto-fixable. Written for the AI to read, not you.

⬇️
💾

Always there, machine-readable

It's rewritten every check — even when clean (an empty list). That's the contract the next step reads. (Once we fix the "blank receipt" gap so it's never empty-by-accident.)

Part 6 · how we FORCE the AI to fix it

🧩

Three jobs, kept apart

1) Detect (the watcher) · 2) Deliver (show the findings) · 3) Enforce (block the finish, not the fixing). Today 1 and 2 exist; 3 doesn't — that's the work.

⬇️
to build 🧰

Way 1 — make the watcher the AI's "build" button

If the AI's build/test step is the watcher, the findings come straight back in the same result. It can't not see them. Works in any tool — the simplest lever.

⬇️
to build 🔄

Way 2 (OMP) — check on each edit, block the finish

After each Edit/Write, an add-on runs the watcher in the async tool_result hook and remembers a red state (tied to the file's hash). It shows the findings to the AI (sendMessage) — but showing isn't forcing. The teeth: a tool_call block on the finish / commit / next-task steps while red, while still allowing Edit/Write so it can actually fix.

⬇️
to build 🚪

Way 3 (Claude Code) — same idea, its own hooks

Claude Code hooks after each edit (PostToolUse) to run the watcher and hand back the findings, and a Stop hook to block "finished" while red. Same rule: block the finish, keep edits open.

⬇️
🛡️

Block the finish, not the fixing

Never block Edit/Write — that would stop the AI from fixing. Block only the finish, commit, and "next task" steps while red. The AI stays free to edit, but can't declare done or move on until it's green. (A plain Stop/CI gate is the last-resort version of this.)

⬇️
⛓️

The loop

Save → check → red exit + receipt → findings pushed to the AI → AI fixes → save → repeat, capped. Still red after the cap? Stop and call a human.

Part 7 · the build order to get robust

step 1 1️⃣

Make red mean red

Exit non-zero when not green. Tiny change — it unlocks every gate above.

⬇️
step 2 2️⃣

Always write a real receipt

Never a blank note on tool/unclear failures — every not-green must explain itself in findings.json.

⬇️
step 3 3️⃣

Wire the per-turn / per-edit check

Build the enforcement in Part 6 — the watcher-as-build-button first, then the turn/edit hook, with the "done" gate as backstop.

⬇️
step 4 4️⃣

Tighten the fixers

Only apply truly-safe edits; stop firing all three project-wide; fix the expected/got flip.

⬇️
step 5 5️⃣

Prove the watch loop; add cancel

Test the live loop for real, and let a new save stop a stale check so it stays responsive.

⬇️
step 6 6️⃣

More languages + insist on tests

Add Python/Go/JS and a lint/type stage — and require tests, so silent wrong answers get caught too.

🎯

The short version

The detector is real: a Rust v1 that catches loud bugs on save and writes a receipt. The missing heart is enforcement — make red exit non-zero, always leave a receipt, and force the AI to fix on every save/turn before it moves on, with a "done" gate only as a backstop. Then the AI is checked as it goes, not trusted at the end.
